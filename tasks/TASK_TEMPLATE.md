## Ограничения

- не изменять `main` напрямую;
- не выполнять force push;
- не коммитить `.env`, секреты, токены, webhook и персональные данные;
- не подключать рабочий Bitrix24 и рабочую 1С без отдельного разрешения;
- не менять несвязанные части проекта;
- не заявлять о выполненной проверке без фактического запуска команды;
- не останавливаться после анализа, если задача технически выполнима.

## Проверки

Минимально выполнить:

```bash
pnpm install --frozen-lockfile
pnpm lint
pnpm typecheck
pnpm test
pnpm build
```

Дополнительно по задаче:

```bash
pnpm exec prisma format
pnpm exec prisma validate
pnpm test:e2e
```

## Git и публикация

1. Создать отдельные атомарные коммиты.
2. Опубликовать ветку.
3. Создать Pull Request в `main`.
4. Не объединять Pull Request автоматически.
5. Проверить GitHub Actions.
6. При ошибке CI изучить логи и исправить в той же ветке.

Если GitHub-аутентификация недоступна, выполнить процедуру экспорта из `docs/WORK_MODE.md`. Не утверждать, что изменения опубликованы.

## Итоговый отчёт

Указать:

- ветку;
- базовый SHA;
- итоговый SHA;
- список коммитов;
- изменённые файлы и функции;
- фактические результаты проверок;
- ссылку на Pull Request либо статус экспорта;
- ограничения;
- следующий этап.
