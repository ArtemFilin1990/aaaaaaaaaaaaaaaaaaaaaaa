# Этап 3 — нормализация и поиск обозначений через PostgreSQL

## Цель
Перевести `/search`, `/catalog` и `/product/[slug]` на серверное чтение канонического каталога PostgreSQL через Prisma без runtime-использования статического массива.

## Границы этапа
Входит нормализация обозначений, разбор явного ГОСТ/ISO intent, размерный поиск, ограниченный fallback по наименованию, DB-backed карточка и простой DB-backed каталог. Не входят фильтры, фасеты, корзина, заказы, цены, остатки, сроки, подтверждение аналогов и запись Bitrix24.

## Поисковый контракт
Хранятся отдельно `rawQuery`, `normalizedQuery`, `parsedIntent` и `generatedVariants`. Пустой запрос возвращает 0 результатов. Максимальная длина входа — 128 символов; внутренний пул — 100 кандидатов; публичный лимит — до 50, по умолчанию 24.

## Критерии приёмки
Результаты приходят из `ProductDesignation`, `SearchAlias`, `StandardMapping`, размеров `Product` и ограниченного name fallback. Каждый результат содержит причину совпадения и предупреждения. Совпадение поиска не является техническим аналогом.

## Обязательные проверки
`pnpm install --frozen-lockfile`, Prisma format/validate/generate/migrate/seed/verify/drift, lint, typecheck, unit, integration, build, Playwright, standalone smoke, `rg "demoProducts" src`, `git diff --check`.

## Ограничения инженерной достоверности
Совпадение размеров не подтверждает взаимозаменяемость. ГОСТ не конвертируется в ISO по размеру. SearchAlias не показывается как официальное обозначение. Публичные цены, остатки и сроки не выводятся.
