# Архитектура каталога

## Границы

Каталог отделяет товар, обозначение, поисковый алиас и инженерную связь аналогов. React-компоненты не должны обращаться к Prisma напрямую; следующий этап добавит `CatalogRepository`.

## Основные связи

- `Brand 1 → N Product`;
- `Category 1 → N Product`;
- `Product 1 → N ProductDesignation`;
- `Product 1 → N SearchAlias`;
- `Product N ↔ N Product` через `AnalogRelation`;
- `ProductDesignation N ↔ N ProductDesignation` через `StandardMapping`;
- `ImportBatch 1 → N ImportRow`.

## Обозначения

`ProductDesignation.value` сохраняет исходное написание. `normalizedValue` предназначено только для поиска и дедупликации в пределах товара и системы обозначения.

Нормализация не должна уничтожать значимые префиксы или самостоятельно признавать два обозначения взаимозаменяемыми.

## Аналоги

`AnalogRelation` направлена от исходного товара к кандидату. Обратная связь не предполагается автоматически. `DIRECT` требует источника и совпадения критичных параметров. `SIZE_ONLY`, `PARTIAL` и `CONFLICT` всегда отображаются с предупреждением.

## Демонстрационные данные

`prisma/seed.mjs` создаёт 33 DEMO-позиции серий 6203, 6204, 6205, 6206, 6304, 6305, 6306, 30205, 30206, 30305, NU205, NJ205, NU206, 7205 и 7306.

Seed использует `upsert` по стабильным уникальным ключам и при повторном запуске не создаёт дубли товаров, обозначений, алиасов и стандартных соответствий.
